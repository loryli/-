# 三餐记 · 设计确认书

> 状态：已与用户逐条确认（2026-10-21）。本文是实现和验收的唯一口径，代码与本文冲突时以本文为准，改本文需先确认。

## 1. 产品定位

安卓端个人饮食热量记录工具：记录一日三餐吃了什么、多少克、多少热量，长期打卡并复盘。

- **单机离线**：无账号、无云同步、无网络请求（首版零 INTERNET 权限）。
- **中文界面**，`kcal` + `g` 单位。
- 名称「三餐记」，包名 `com.my.mealjournal`。

## 2. 已确认决策

| # | 决策 | 结论 |
| --- | --- | --- |
| Q1 | 记录粒度 | 一餐 = N 条食物条目；热量 = 克数 × 每 100g 热量 |
| Q2 | 食物库 | 内置约 200 条常见中文食物 + 用户自建食物；不接在线 API |
| Q3 | 打卡判定 | 早/午/晚各至少 1 条 = 完整；有记录但不足三餐 = 部分；无记录 = 缺失 |
| Q4 | MVP 边界 | 只做餐饮 + 热量 + 打卡；体重/喝水/运动不做 |
| Q5 | 视图 | 今日 / 日历热力图 / 统计 / 我的食物 / 设置 |
| Q6 | 底座 | Kotlin + Compose + Room，`minSdk 26` / `targetSdk 36` / `compileSdk 36`，CSV 导出 |
| R2-1 | 热量目标 | 用户手填或档位（1200/1500/1800/2200），不强制算 BMR |
| R2-2 | 补记 | 可补记/修改最近 7 天；更早只读 |
| R2-3 | 餐次归属 | 按时间自动判定（05–10 早、10–15 午、15–21 晚、其余加餐），可手动改 |
| R2-4 | 提醒 | 本地通知，默认每天 20:00，可改时间、可关闭 |
| R2-5 | 食物库数值 | 公开近似值，UI 标注"参考值"；支持导入自有 CSV |
| Q7 | 计量方式 | 克数 + 可选「份量单位」（个/碗/杯…）；添加和编辑都能切 |
| Q8 | 单位来源 | 食物库自带单位与每份克数；自定义食物可填，留空则只能按克 |
| Q9 | 存储口径 | entries 只存 grams，单位不落库；展示时按 food 的 unit_label/unit_grams 现场换算，食物删除后回落为克 |
| Q10 | 份量精度 | 允许 0.5 份；换算后克数保留 1 位小数，热量按克数算 |
| Q11 | 份量 UI | 添加面板底部「克 / 单位」分段按钮 + 数量输入，实时显示「约 X kcal · Y g」 |
| Q12 | 默认值 | 选食物后默认 1 份；无单位的食物默认 100 g |
| Q13 | 列表展示 | 条目副标题显示「N 单位 · Y g」，只读旧条目显示「1 份 · 100 g」 |
| Q14 | 迁移 | 数据库 1→2：foods 加 unit_label/unit_grams 两列；内置食物按清单补单位；历史条目不变 |
| Q15 | 营养素数据 | foods 加蛋白/碳水/脂肪（每 100g，可空 = 未知）；内置 161 条全补公开近似值；自定义食物可选填 |
| Q16 | 条目快照 | entries 存按克数算好的 protein/carbs/fat 快照（与 kcal 同口径）；编辑克数时等比缩放；迁移 2→3 按当前食物数据回填历史条目，食物缺失保持 0 |
| Q17 | 营养目标 | 不做用户画像，由目标热量按固定供能比推导：碳水 50% / 蛋白 20% / 脂肪 30%（系数 4/4/9 kcal/g），暂不做设置项 |
| Q18 | 视觉方向 | 薄荷健康式：清新薄荷绿主色 + 纯白大圆角卡 + 冷白底；营养素固定三色（碳水蓝/蛋白紫/脂肪橙）；保留深色模式；字阶/圆角/间距 token 沿用 |
| Q19 | 无网边界 | 薄荷的食物图片、扫码、在线食物库、社区商城均依赖网络，与单机离线底线冲突，明确不做 |

## 3. 数据模型（Room）

```text
foods
  id            INTEGER PK AUTOINCREMENT
  name          TEXT NOT NULL
  kcal_per_100g REAL NOT NULL
  category      TEXT NOT NULL          -- 主食/肉蛋/蔬菜/水果/奶豆/零食/饮品/其他
  unit_label    TEXT                   -- 碗/个/杯，可空
  unit_grams    REAL                   -- 一个单位约多少克，可空
  protein_per_100g REAL               -- 可空 = 未知，只按热量记
  carbs_per_100g   REAL
  fat_per_100g     REAL
  is_builtin    INTEGER NOT NULL       -- 1=内置，0=自建
  created_at    INTEGER NOT NULL

entries
  id            INTEGER PK AUTOINCREMENT
  date          TEXT NOT NULL          -- ISO-8601 本地日期 yyyy-MM-dd
  meal          TEXT NOT NULL          -- BREAKFAST/LUNCH/DINNER/SNACK
  food_id       INTEGER                -- 可空：食物被删后置空
  food_name     TEXT NOT NULL          -- 快照，防止改食物名改写历史
  kcal_per_100g REAL NOT NULL          -- 快照
  grams         REAL NOT NULL
  kcal          REAL NOT NULL          -- 冗余存，便于统计
  protein       REAL NOT NULL DEFAULT 0  -- 快照：按克数算好的三大营养素
  carbs         REAL NOT NULL DEFAULT 0
  fat           REAL NOT NULL DEFAULT 0
  created_at    INTEGER NOT NULL
  INDEX(date), INDEX(date, meal)
```

**快照规则**：entry 保存 `food_name` / `kcal_per_100g` / `kcal` / 三大营养素的副本。之后改食物库不追溯改写历史；编辑克数时 kcal 重算、营养素等比缩放。

**营养口径**（Q15–Q17）：食物营养为公开近似参考值，未知按 0 参与合计（热量口径不受影响）；目标 = 目标热量 × 供能比（50/20/30）/ 供能系数；酒精供能（啤酒/白酒）不计入三大营养素。

**单位规则**（Q7–Q14）：`grams` 是唯一事实来源；单位只用于录入/展示时换算，历史记录不存单位，食物删掉后自动回退为克数视图。

**只读规则**：`today - date > 7 天` 的 entry 不可新增/修改/删除（保留历史可信度）。补记后 streak 重算。

## 4. 业务口径

- **日状态**：`COMPLETE`（三餐都有条目）/ `PARTIAL`（有条目但不满三餐）/ `MISSING`。
  - 加餐（SNACK）不参与完整度判定，但计入热量。
- **连续天数 streak**：从今天（若今天未完整则从昨天）往前数连续 `COMPLETE` 的天数；中间断一天即停。
- **目标进度**：`今日总热量 / 目标热量`；超出目标仅用中性提示"已超出 X kcal"，不做红色羞辱。
- **统计**：近 7 / 30 天平均热量、达标天数（不超目标）、最长连续天数、各餐热量占比。
- **日历热力图**：月视图，颜色深浅 = 当日完成度（缺失/部分/完整 三档）+ 超出目标标记。

## 5. 交互要点

- 首页「今天」：日期 + 三张餐卡片（每张显示条目数与小计热量）+ 总热量进度 + 快捷"记一笔"。
- 记一笔：选餐次（默认按时间）→ 搜食物 / 选我的食物 → 输克数或切「份量单位」按个/碗 → 保存。
- 编辑条目：同一套「克 / 单位」切换，改哪个都保留原记录单位，保存后列表副标题显示「N 单位 · Y g」。
- 日历：点日期进入该日详情；7 天内可编辑，更早已只读。
- 设置：目标热量（档位 + 自定义）、提醒开关与时间、导出 CSV、关于。

## 6. 非目标（本版明确不做）

账号体系、云同步、体重/喝水/运动模块、拍照识别、营养元素（蛋白/脂肪/碳水）分析、多语言、平板适配、widget。

### 2026-10-21 第二轮：按份计量（Q7–Q14）

- 新增 `domain/Portion.kt`（`displayUnit` / `describe` / `toPortion` / `formatAmount`），配套 6 个单测。

| 项 | 偏差 | 原因 |
| --- | --- | --- |
| Q2 食物库 | 内置约 150 条，不是 200 条 | 首版够用，后续按实际缺口补 |

### 2026-10-22 第四轮：交互提速（R4-1–R4-6）

用户拍板：Q1–Q6 都按推荐。

- 记录去重：从餐次卡片打开面板时隐藏餐次 chips，只显示「记到 午餐」；只有 FAB「记一笔」才给选餐次。
- 最近记录改成一步：点 chip 直接按上次克数记一条（`lastGrams(foodId)`，没有历史就退回单位克数或 100g），4 秒内 Snackbar「撤销」删掉；长按 chip 才展开份量。
- 删除不再弹二次确认：直接删 + Snackbar「已删除 XX / 撤销」，撤销把实体按原记录插回。
- 数量输入加台阶：克数 ±10 / 长按 ±50；份量 ±0.5 / 长按 ±5。
- 日历左右滑动切月（阈值 80px），箭头保留。
- 提醒变聪明：到点先查当天 entries，三餐空 → 不发；缺哪几餐 → 标题「今天还差 午餐、晚餐」，正文「补上 午餐、晚餐 就完整打卡了」。顺带修掉 `ReminderScheduler.nextTrigger` 把 minuteOfDay 当秒传给 `LocalTime.ofSecondOfDay` 的 bug（默认 20:00 实际排到 00:20），补 `ReminderScheduleTest` 3 个用例。

验证：单元测试 30 个全过；模拟器实测点卡片打开面板、点最近记录一步记入、撤销新增/撤销删除、长按步进 +5 份、日历滑动切月；`dumpsys alarm` 显示设定后下一秒触发时间符合预期。
